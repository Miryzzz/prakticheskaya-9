# Практическая работа № 9
## «Мини-релиз веб-проекта в GitHub»

**Цель:** закрепить навыки командной работы с GitHub и научиться доводить изменение от задачи до принятия в основную ветку.

## 5. Выполненные действия
1. Создан исходный сайт в main.
2. От общей исходной версии main созданы ветки feature/contacts-html и feature/contacts-style.
3. В HTML-ветку добавлены раздел контактов и ссылка в меню.
4. Открыт [Pull Request № 1](https://github.com/Miryzzz/prakticheskaya-9/pull/1).
5. До исправления оставлено замечание в review: e-mail должен быть кликабельным.
6. В ту же ветку добавлен отдельный коммит с mailto:, текущий PR обновился.
7. Выполнена повторная самопроверка. Независимый Approve не выполнен: доступен только один аккаунт.
8. Pull Request № 1 объединён в main.
9. CSS оформлен в отдельной ветке; [Pull Request № 2](https://github.com/Miryzzz/prakticheskaya-9/pull/2) проверен и объединён в main.
10. Итоговые файлы проверены в main. Ветки сохранены для демонстрации.

**Ограничение:** оба PR и review-комментарии созданы от Miryzzz. Это учебная самопроверка, а не работа двух независимых участников. Для полного выполнения командной части необходим второй аккаунт и настоящее Approve.

## 6. Проверка reviewer (по готовым файлам)
| Проверка | Да/Нет | Комментарий |
|---|---|---|
| Изменение соответствует заданию | Да | Есть раздел «Контакты» |
| Раздел contacts добавлен в правильном месте | Да | Перед footer |
| В меню есть переход к #contacts | Да | Ссылка в nav |
| Телефон, e-mail и адрес присутствуют | Да | Все три поля есть |
| В первой версии обнаружен некликабельный e-mail | Да | Замечание сохранено в review PR № 1 до исправления |
| После исправления используется mailto: | Да | Ссылка mailto:info@example.ru |
| HTML/CSS остаётся читаемым | Да | Простая структура |
| Нет случайно удалённого содержимого | Да | Все основные секции сохранены |
| Сообщения коммитов понятны | Да | История коммитов доступна в репозитории |
| Изменения можно объединить с main | Да | Оба PR объединены |

## 8. Контрольные вопросы
1. Чтобы изменения проходили проверку и не ломали стабильную основную ветку.
2. Чтобы работать над отдельной задачей независимо от `main`.
3. Новые коммиты автоматически появляются в уже открытом Pull Request.
4. Чтобы посмотреть конкретные изменения в файлах и найти ошибки.
5. Комментарий содержит замечание, а Approve подтверждает одобрение изменений.
6. Исправление добавляется в ту же ветку и автоматически обновляет текущий PR.
7. Проверить сайт, ссылки, стили, содержимое `main` и отсутствие ошибок.

## Итог
В main находится сайт с разделом «Контакты», ссылками tel: и mailto: и CSS-оформлением. Два Pull Request объединены. История первого PR содержит замечание и последующее исправление отдельным коммитом. Независимое ревью и Approve второго участника не выполнены.
